四、配置服务器部署脚本

部署脚本负责以下工作：

  1. 确定部署分支，默认使用 test。
  2. 将服务器源码重置为远程分支的最新状态。
  3. 使用项目规定的 Node 和 pnpm 构建测试包。
  4. 先把完整 dist 同步到 S3。
  5. S3 同步成功后，再更新本地 index.html。

参考结构如下：

其中：

  • set -e：任意命令失败后立即停止脚本，避免上传失败后继续切换入口文件。
  • BRANCH=$1：允许通过第一个参数指定分支。
  • git reset --hard：丢弃已跟踪文件的本地修改。
  • git clean -fd：删除未被 Git 管理的文件和目录。
  • nvm use：读取项目 .nvmrc，当前项目使用 Node 24.14.0。
  • pnpm run build:test：执行 vite build --mode test，读取 .env.test。
  • aws s3 sync：将构建产物同步到 S3，--size-only 只同步大小变化文件，--acl public-read 设置公开访问权限。
  • cp dist/index.html：静态资源准备完成后，切换服务器入口文件。

git reset --hard 和 git clean -fd 会删除服务器源码目录中的本地改动，不能在该目录保存未提交文件。

九、配置完成与首次发布验收

发布前检查

  • 创建并推送 test 分支。
  • 确认 CDN 地址及 Vite base。
  • 确认 API、SSO 回调地址、后端跨域白名单和 OpenResty 配置。
  • 确认 <deploy-test> Runner 在线。
  • 确认 deploy-ui.sh 具有执行权限。

发布后验收

  • Pipeline 构建、S3 上传和通知全部成功。
  • S3 中存在最新静态资源。
  • 服务器入口目录生成 index.html。
  • 构建后的资源 URL 指向 CDN。
  • 首页、/sso 和其他 History 路由可以正常访问。
  • 浏览器没有资源 404、CORS 或 MIME 类型错误。
  • 登录、权限获取和页面刷新正常。
